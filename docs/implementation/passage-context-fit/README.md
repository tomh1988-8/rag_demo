# Captured passage fit

Review baseline: `acfad8a635cb8d0d71dbb42b82a9133716c872de`.
Specification: candidate 01 from the architecture review, selected for implementation
by the user on 17 October 2026.

The frozen eight-source sample currently produces 138 admitted passages. Of these,
67 cannot fit alone in the 1,200-byte answer context: ingestion sizes raw text,
while context serialization also includes evidence identifiers, source titles and
JSON escaping. For example, `sharon-wiki-0053-50624` has 1,198 text bytes but needs
1,280 serialized bytes, so context assembly excludes it.

## Behavior and test seams

- Concentrate passage preparation, serialization and context selection in one
  in-process module. Measure the actual serialized representation when preparing
  passages; retain the existing 1,200-byte answer-context budget and the separate
  1,800-byte embedding-input budget.
- Preserve every admitted source span, exact Unicode offsets, character links,
  reviewed scope and whole-passage citations. Handle metadata, escaping and
  multibyte text without dropping source text or splitting a Unicode character.
- Include projection policy in refresh input identity. An unchanged captured batch
  prepared with the revised policy gets new immutable artifacts; an unchanged
  rerun under the same policy reuses them. Retain prior snapshots and citations,
  including their original serialized shape, for inspection and recovery.
- Test through the existing import, context/citation, answer and refresh/recovery
  interfaces, with real PostgreSQL/pgvector and Prefect for lifecycle checks.
  Substitute only external model/source transport in routine tests.

ADRs 0003, 0004, 0006 and 0007 continue to apply. Wider context expansion and
multi-query retrieval retain issue #24's scope. Model accounting and publication
readiness remain the other architecture-review candidates.

## Validation

The frozen sample now produces 147 passages; every passage fits alone and the
largest serialized context is exactly 1,200 bytes. The context module owns
projection, serialization, size accounting and whole-passage selection. Existing
imports of `assemble_context` and `context_text` remain available through
`ask_phil.answers`.

New imports record `html-context-fit-v2`. Refresh input fingerprints include that
projection version; capture check times remain excluded. Retained
`html-paragraphs-v1` snapshots still deserialize with their original document
shape. The synthetic v1 fixture was generated by the baseline implementation,
including its original pre-versioned input identity.

The real-source citation regression failed first on
`sharon-wiki-0053-50624`, then passed after the sizing change. The migration
regression reproduced refresh reporting `skipped`, then passed after versioning:
v1 publication → v2 publication → unchanged skip → v1 recovery, with
generations 1 → 2 → 3 and identical historical evidence before and after recovery.
Additional cases cover multibyte text without spaces, JSON escaping, source titles,
continuous exact offsets and a complete answer/citation/receipt through real
PostgreSQL, pgvector and MLflow with controlled external model transport.

The full suite passed **137 tests**, with no failures, errors or skips, in 197.21
seconds using the local Python virtual environment, isolated pinned
PostgreSQL/pgvector and real Prefect. [JUnit](software-tests.xml) and
[validation identities](validation.json) bind those results to the source, tests,
frozen input and application fingerprint. Ruff and strict mypy (38 source files)
passed. The [independent Standards and Spec reviews](review.md) each have zero
findings. The only suite warning is the existing upstream Starlette/httpx
test-client deprecation.

These checks establish passage fit and lifecycle behavior; they do not measure
retrieval ranking or factual answer quality. No paid model calls or live source
captures were needed.

## Applying the revised projection

Run the existing reviewed refresh workflow against the retained captured batch:

```sh
uv run ask-phil refresh-sources data/sources/real-sources-v1.json.gz
```

The new projection gets a new snapshot/index identity even for unchanged source
bytes. An unchanged rerun reuses the new artifacts. Existing v1 snapshots,
historical citations and saved responses keep their original meaning, and
recovery can restore their compatible artifacts. For explicit `import-sources`
commands, choose a new snapshot identifier; stored identifiers remain immutable.
