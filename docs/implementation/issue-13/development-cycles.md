# Development checks at the confirmed seams

The existing six-boundary strategy already authorises these seams; the user also
confirmed the issue-specific selection and review baseline `8c19539` during this
implementation. No tests use private application methods or mocked internal stores.

The public claim/admission cycle began with guilt counterexamples: allegation,
confession and legal outcome cannot establish commission, and a narrative label
without an explicit narrative support review is insufficient. Initial collection
failed because the new domain module did not exist. The next rule cycle produced
five actual assertion failures for participant role, uncertainty, negation, timing
and performer identity before those admission checks were implemented. Source-bound
review, bad quote, opposite-account and inconsistent-incident counterexamples then
protected conservative admission.

The stored graph cycle first failed because the shared-event tool did not exist.
After implementation, a real PostgreSQL query returned all other participants in
the selected incident, preserving Bobby's perpetrator role, Lucy's victim role and
Max's legal involvement without transferring guilt.

The API cycle first returned HTTP 422 for the missing typed event-query contract.
The CLI cycle rejected its then-unknown `--crime-history` option. The capability
counterexample initially returned a supported answer under a family-only policy;
adding the distinct `event_graph` capability made it stop with capability_denied.
The broad-history probe exposed the existing context bound; selecting an incident
provided a supported answer while broad requests retained their limit outcome.

Independent review found the source-label timing omissions. The API regression
actually failed on missing `story timing later (relative)` before the versioned
correction. Duplicate-support prose separately failed with two copies instead of
one before grouping identical source-anchored assertions. Both source records stay
in the public typed result and audit.

Focused claim, scorer, extraction-run, graph/API and CLI files were run throughout.
The controlled extraction-run tests exercise the actual retained-result and MLflow
path with substituted external provider HTTP and disposable ledgers. They do not
charge the shared trial or establish live model quality. Strict mypy was run
regularly and passed across all 90 source/test/script files after the final fixes.
The first complete full suite ran 387 cases: 386 passed and one existing
concurrent-session case exposed a fixed five-second SQL lock-wait mismatch.
A controlled slow-model counterexample reproduced that failure, and both it
and the original concurrency case pass after bounded, cancellable row acquisition.
Independent review also closed a post-wait deadline race. The final full run
follows those necessary fixes; both software reports remain separate from
model-quality evidence.
